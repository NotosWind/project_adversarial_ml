# Итеративный состязательный атакователь ML-модели

Учебный проект по дисциплине «Проектная деятельность».

Система в автоматическом режиме демонстрирует противоборство **«атака ↔ защита»** для
свёрточной нейросети на наборе MNIST:

1. Базовая модель атакуется состязательной атакой из библиотеки **ART** (FGSM / PGD) — точность под атакой **падает**.
2. Применяется **состязательное обучение (adversarial training)** — точность под атакой **растёт**.
3. Цикл повторяется **10 итераций** («гонка вооружений»), метрики и графики сохраняются.

Дополнительно: эксперимент с ростом силы атаки ε и экспорт итоговой устойчивой модели в **ONNX**.

**Главный результат (реальный прогон на GPU):** атака PGD роняет точность базовой модели
с **98.8 % → 2.0 %**; после 10 итераций состязательного обучения устойчивость к PGD —
**92.3 %** при сохранении точности на чистом тесте (~98.7 %); успех атаки падает с **98 % → 8 %**.

## Быстрый старт на новой машине (git clone → запуск)

```bash
# 1. Получить проект
git clone <URL-вашего-приватного-репозитория> project_adversarial_ml
cd project_adversarial_ml

# 2. Установить зависимости в изолированное окружение .venv (кроссплатформенно)
python install.py

# 3. Запустить весь пайплайн одной командой
#    Windows:
.\.venv\Scripts\python.exe run_all.py
#    Linux / macOS:
./.venv/bin/python run_all.py
```

Всё. После прогона смотрите графики в `results/figures/`, метрики — в `results/metrics.csv`,
документы для защиты — в `docs/`.

> **GPU (опционально).** По умолчанию ставится CPU-версия PyTorch — работает везде, но медленнее.
> Если на машине есть видеокарта NVIDIA, поставьте CUDA-сборку torch в окружение `.venv`
> по инструкции <https://pytorch.org/get-started/locally/>. Код сам определит GPU и использует его.

### Ручная установка (без install.py)

```bash
python -m venv .venv
# активация: Windows  .\.venv\Scripts\Activate.ps1   |   Linux/mac  source .venv/bin/activate
python -m pip install --upgrade pip
```

## Что делает каждый шаг

**`scripts/train_baseline.py`** — обучает CNN на MNIST (3 эпохи) и сохраняет «модель на входе»
в `models/baseline.pt`. Печатает точность на чистом тесте (≈ 99 %).

**`scripts/run_experiment.py`** — основной эксперимент:
- загружает модель из файла `.pt` («модель приходит на вход атакователю»);
- 10 итераций: атака PGD/FGSM → замер (точность падает) → состязательное обучение → замер (точность растёт);
- сохраняет метрики (`results/metrics.csv`) и графики (`results/figures/`);
- дополнительный эксперимент: устойчивость от силы атаки ε (`epsilon_sweep`);
- экспортирует устойчивую модель в `models/robust_final.onnx` и сверяет выходы с onnxruntime.

## Теория (кратко)

- **Состязательный пример** — почти неотличимый от исходного вход `x' = x + δ` (`‖δ‖∞ ≤ ε`),
  который модель классифицирует неверно.
- **FGSM** (Goodfellow, 2014) — одношаговая атака по знаку градиента.
- **PGD** (Madry, 2017) — итеративная атака, «сильнейшая атака первого порядка».
- **Состязательное обучение** — дообучение на состязательных примерах; решает минимаксную задачу
  `min_θ E[ max_δ J(θ, x+δ, y) ]`.

Подробнее — в `docs/design_spec.md` и пояснительной записке.
