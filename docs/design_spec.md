# Техническое задание и дизайн проекта

**Тема:** Итеративный состязательный «атакователь» ML-модели с защитой через состязательное обучение
**Дисциплина:** Проектная деятельность
**Стек:** Python 3.12, PyTorch (CUDA), Adversarial Robustness Toolbox (ART)
**Дата:** 2026-06-04

---

## 1. Цель проекта

Разработать программную систему, которая в автоматическом итеративном режиме демонстрирует
противоборство «атака ↔ защита» для модели машинного обучения:

1. На вход подаётся обученная ML-модель (файл выбранного формата).
2. Модель атакуется состязательной атакой из библиотеки ART — её качество (точность) под атакой падает.
3. Применяется защита — **состязательное обучение (adversarial training)** — качество под атакой растёт.
4. Цикл повторяется **10 итераций**, формируя «гонку вооружений» между атакующим и защитником.

## 2. Задачи

- Обучить базовую модель-классификатор (CNN) на наборе данных MNIST.
- Реализовать модуль-«атакователь», принимающий модель из файла и применяющий атаки ART (FGSM, PGD).
- Реализовать модуль защиты — состязательное обучение (дообучение на состязательных примерах).
- Реализовать оркестратор итеративного цикла на 10 итераций с логированием метрик.
- Визуализировать результаты (кривые точности, примеры искажённых изображений).
- Экспортировать итоговую устойчивую модель в формат ONNX.
- Подготовить пояснительную записку (.docx) и презентацию (.pptx).

## 3. Теоретическая основа

### 3.1. Состязательные примеры (adversarial examples)

Состязательный пример — это вход `x' = x + δ`, визуально неотличимый от исходного `x`
(`‖δ‖∞ ≤ ε`), но приводящий модель к ошибочному предсказанию. Их существование показано
Szegedy et al. (2013) и объяснено гипотезой линейности Goodfellow et al. (2014).

### 3.2. FGSM (Fast Gradient Sign Method), Goodfellow et al., 2014

Одношаговая атака: сдвиг входа на величину `ε` в сторону знака градиента функции потерь.

```
x' = x + ε · sign(∇ₓ J(θ, x, y))
```

Быстрая, но относительно слабая.

### 3.3. PGD (Projected Gradient Descent), Madry et al., 2017

Итеративное (многошаговое) усиление FGSM с проекцией на ε-окрестность `S` после каждого шага:

```
x⁰ = x + случайный шум в пределах ε
xᵗ⁺¹ = Proj_S( xᵗ + α · sign(∇ₓ J(θ, xᵗ, y)) )
```

Считается «сильнейшей атакой первого порядка» и стандартом для оценки устойчивости.

### 3.4. Adversarial Robustness Toolbox (ART)

Библиотека Linux Foundation AI для исследования устойчивости ML. Предоставляет единый
интерфейс «классификатор + атака»: модель оборачивается в `PyTorchClassifier`, затем к ней
применяются `FastGradientMethod`, `ProjectedGradientDescent` и др. Используется в проекте как
источник атак и обёртка модели.

### 3.5. Состязательное обучение (adversarial training), Madry et al., 2017

Защита: модель дообучается на состязательных примерах, сгенерированных «на лету» против
текущих весов. Формально — решение минимаксной задачи:

```
min_θ  E_(x,y)[ max_{‖δ‖∞≤ε}  J(θ, x+δ, y) ]
```

Внутренний максимум приближается атакой (PGD), внешний минимум — обычным обучением.

## 4. Данные и модель

- **Данные:** MNIST (70 000 изображений рукописных цифр 28×28, градации серого, значения [0,1]).
  Загрузка — через `art.utils.load_mnist()` (скачивается и кэшируется автоматически, без torchvision).
- **Модель:** свёрточная нейросеть (CNN):
  `Conv(1→32, 3×3) → ReLU → Conv(32→64, 3×3) → ReLU → MaxPool(2) → Dropout(0.25) →`
  `Flatten → FC(9216→128) → ReLU → Dropout(0.5) → FC(128→10)`.
  Базовая точность на чистом тесте ≈ 99 %.

## 5. Форматы модели (требование «формат выбираете сами»)

- **Основной — pickle (PyTorch `.pt`)**: атакователь принимает модель именно как файл `.pt`
  (`torch.save`/`torch.load` используют pickle). Это удовлетворяет пункту «pickle».
- **ONNX**: итоговая устойчивая модель дополнительно экспортируется в `.onnx`
  (`torch.onnx.export`) и проверяется через `onnxruntime`. Это удовлетворяет пункту «ONNX»
  и демонстрирует переносимость модели между фреймворками.

## 6. Методика эксперимента

### 6.1. Основная схема — адаптивная «гонка вооружений» (10 итераций)

На каждой итерации `i = 1..10`:

1. **Загрузка** текущей модели из файла, обёртка в ART `PyTorchClassifier`.
2. **Атака**: PGD-атака против *текущей* модели → состязательные примеры → замер точности
   под атакой (**падает**). Дополнительно замер под FGSM для сравнения.
3. **Защита**: одна эпоха состязательного обучения по Madry — для **каждого батча**
   генерируются PGD-примеры против текущих весов, и на них делается шаг оптимизации
   (постоянный оптимизатор сохраняется между итерациями) → замер точности под той же
   атакой (**растёт**).
4. **Логирование** метрик, сохранение модели итерации (`robust_iter{i}.pt`).

Оценка устойчивости каждую итерацию ведётся атакой PGD из ART при **фиксированной**
конфигурации, поэтому кривая «точность под атакой после защиты» сопоставима между
итерациями и растёт.

> **Важная деталь реализации.** Состязательные примеры для обучения генерируются
> заново для каждого батча против текущих весов. Если генерировать их один раз за
> итерацию по фиксированной подвыборке, модель «запоминает» конкретные возмущения, но
> остаётся уязвимой к свежей адаптивной атаке — устойчивость не растёт. Per-batch
> регенерация устраняет эту проблему.

### 6.2. Дополнительный эксперимент — эскалация ε

Для базовой и итоговой устойчивой модели строится зависимость «точность под атакой от силы
атаки `ε ∈ {0.05 … 0.30}`». Показывает выигрыш защиты и её предел при усилении атаки.

## 8. Метрики и артефакты

**Метрики (на каждой итерации, в `results/metrics.csv`):**

- `clean_acc` — точность на чистом тесте;
- `fgsm_acc_before` — точность под FGSM до защиты этой итерации;
- `pgd_acc_before` — точность под PGD до защиты;
- `pgd_acc_after` — точность под PGD после состязательного обучения;
- `attack_success_before` = 1 − `pgd_acc_before`.

**Графики (`results/figures/`):**

- `accuracy_curves.png` — чистая / FGSM / PGD(до) / PGD(после) по итерациям;
- `attack_success.png` — успех атаки по итерациям;
- `adv_examples_grid.png` — сетка «оригинал → искажение → предсказание»;
- `epsilon_sweep.png` — устойчивость базовой vs итоговой модели от ε.

## 9. Параметры эксперимента

| Параметр | Значение |
|---|---|
| Набор данных | MNIST, значения в [0, 1] |
| Базовое обучение | Adam, lr=1e-3, batch=128, 3 эпохи |

| Подвыборка для оценки атак | 2000 тест-изображений |
